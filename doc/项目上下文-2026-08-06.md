### 新的四个设计信号

1. AdaCoM / learning agent-compatible context management
   context management 不应该只是 summarization，而应该是一个外置、可学习、可复用的 context controller；并且不同 agent 需要不同 fidelity / reliability 策略。

2. MemAct / memory as action
   memory editing 应该被视为 policy action，而不是旁路工具；这会让 memory mutation 有自己的 credit assignment、trajectory fracture 和 replay split point。

3. Durable intermediate artifacts
   中间工件应该是 typed、addressable、versioned、dependency-aware、authoritative 的 maintained state；评估不能只看 final output，要看 maintained-state quality。

4. Evidence tracing / execution provenance
   trace 不只是 log，而是 execution provenance graph；evidence tracing 是这个图到 evidence-support relation 的投影。回放与诊断应围绕这个图展开。

5. State proprioception / selective turn memory
   agent 需要“看见自己的上下文状态”，否则 context management 仍然是隐藏层；turn-level memory 也要保留来源和证据，不然 credit assignment 和 replay reconstruction 都会断。

## 2. 对 Harness x Hermes 的设计增量

### 2.1 Context 变成 control plane

我们现在的 context 设计应该从“内容压缩”升级成“上下文控制面”：

- retain / drop / compress / pin / branch / rehydrate
- 记录 context action 的来源、原因和后效
- 把 context policy 和 context lineage 独立出来
- 给 agent 一个可观测的 context dashboard，而不是把所有 context 变化藏在黑盒 summary 里

这比单纯做 summary/checkpoint 更接近真正的长程 agent runtime。

### 2.2 Artifact 变成 first-class state

Hydration manifest 不应只恢复状态快照，还要恢复：

- artifact lineage
- current-state resolution
- supersession history
- dependency graph

这能把“能不能复现”推进成“复现时能不能解释当前态为何成立”。

### 2.3 Trace 变成 provenance graph

TraceEnvelope 后续应当更明确地编译为：

- execution provenance graph
- evidence support graph
- replay diagnosis graph

这样 replay 不再只是比对日志，而是检查证据是否仍然支持当前决策链。

### 2.4 Footprint 变成正式预算

AgentFootprint 这条线说明 storage / checkpoint / artifact / trace 的体量本身就是评估维度。
所以后续 runtime 应该显式报告：

- checkpoint bytes
- artifact bytes
- trace bytes
- context retention bytes

## 6. 今天继续补到的设计信号

今天又多补了几篇更直接指向 runtime 架构的论文/技术报告，它们把我们的设计边界再收紧了一层：

- ResearchLoop 把 research lifecycle 本身做成 evidence-gated control plane，这和我们想把 harness / session / closeout 做成 durable state 很一致。
- AgentTrails 把 raw trajectory 编译成 provenance graph，再做共享 canvas / quotient graph / reuse，这说明 trace 应先成为图，再谈 replay。
- Traccia 把 OpenTelemetry、passive guardrail assessment、execution lineage 和 hashed trace ledger 绑定起来，这很像我们后续要做的 telemetry-backed governance package。
- Verifiable Agentic Infrastructure 把 authorization 从 standing identity 推向 proof-derived authority，意味着 commit-time authorization 未来应该看 proof object 和 evidence chain，而不是只看 approve token。
- Agentic Memory 把 store / retrieve / update / summarize / discard 直接提升为工具动作，说明 memory mutation 本身就是 policy action，不能当成隐式副作用。

所以后面最自然的演化方向就是：

1. context control plane
2. provenance graph
3. proof-derived authorization
4. explicit memory actions

这几件事如果串起来，我们的 runtime 就会比“普通 agent 框架”更像一个真的可审计、可复水、可回放的 long-horizon SE substrate。
